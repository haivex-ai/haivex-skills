# 可选增补：情景分析与投资建议（默认关闭）

> **仅当用户明确追问**情景分析、理论业绩空间/理论 L、高估低估/位置关系、投资建议/买不买/仓位时加载本文件并执行。  
> 默认分析与默认报告**不得**预写本文件内容。  
> 增补必须建立在已完成的客观列示（隐含 L、券商 DCF、阵营、叙事）之上，数字口径同源。

## 一、启用判定

| 用户意图 | 是否启用 | 产出范围 |
| --- | --- | --- |
| 分析公司 / 出穿透叙事报告 / 隐含预期 | 否 | 仅客观列示 |
| 「做一下情景」「理论空间」「四档 L」 | 是-情景 | 情景表 + 正算市值 + 与现价/券商隐含 L 对照 |
| 「贵不贵下个结论」「高估还是低估」「在哪一档」 | 是-位置 | 情景 + 位置关系判断（可无操作建议） |
| 「给投资建议」「买不买」「怎么配仓」 | 是-建议 | 情景 + 位置 + 条件化建议框架 |
| 含糊「怎么看」 | 否（先客观列示）；可提示可追问情景/建议 | — |

一次追问可只开情景、或情景+位置、或全开；**不要**在用户只要情景时强行给买卖喊单。

## 二、情景分析步骤

### 2.1 输入复用

- 市值、股本、E1/E2/E3、E0：`80_financial.*` / 已跑过的 `dcf_implied`
- 行业 TAM、份额、利润率的他人表述：`10_industry.md`、研报/纪要
- 券商隐含 L：`91_brokers.json` 或已有总表

缺 TAM/份额/利润率锚点时再补搜，不推翻已发布的隐含 L 数字。

### 2.2 构造本方情景表（通常四档）

默认档名：**保守 / 基准 / 乐观 / 极乐观**（周期股可改为：周期底部标准化 / 中枢 / 高位 / 泡沫化高位）。

每档必须可审计：

```text
L_i = TAM_i × 份额_i × 净利率_i
```

或（周期/金融等不适用简单乘积时）写清替代路径：峰值利润×归一系数、ROAE×权益等，并说明为何不用三要素。

| 列 | 要求 |
| --- | --- |
| 档名 | 四档（或三档，须说明） |
| TAM / 空间假设 | 数值+单位+来源类型（第三方/券商区间/产能反推） |
| 份额假设 | % + 依据（历史峰值/竞争格局上沿下沿） |
| 净利率假设 | % + 依据（历史、同行、规模效应叙事） |
| L（亿元） | 乘积结果，保留一位小数 |
| 关键假设一句 | 该档「叙事故事」一句话 |
| 正算市值@r=10% | `dcf_implied.py calc --l L --e1 --e2 --e3 --r 10` |
| 对应股价 | 市值/股本（注明币种） |

规则：

1. **禁止**先拍 L 再倒填三要素凑数；允许在合理区间内微调要素使 L 整数好看，但须披露。
2. 保守档不得明显低于行业合计逻辑下的「极端悲观仍可自洽」下沿；极乐观不得无上限狂想，须对应「市场讨论过的上限叙事」或产能/渗透率物理上沿。
3. 基准档应尽可能靠近「中性可讨论」中枢，而非偷偷写成推荐档。
4. 用脚本将现价隐含 L（三档 r）与各券商隐含 L 映射到最近情景档；可调用 `verify_L_vs_scenario` 思路交叉验证。

### 2.3 位置关系表述（情景启用后）

对照表至少含：

- 现价隐含 L（r=8/10/12%）落在情景区间的位置
- 主要券商目标价隐含 L 落点分布
- 一句话位置结论，允许使用：相对本方情景 **偏低估 / 中性 / 偏高估 / 透支上沿** 等——**必须**写明「相对本方情景假设」，禁止写成绝对真理

示例句式（可改编）：

> 在 r=10% 下，现价隐含 L≈X 亿，落在本方情景「乐观–极乐观」之间（本方区间 [A,B]），对应叙事已部分打满上沿假设；若基准情景更可信，则现价隐含终局高于基准约 Y%。

### 2.4 敏感性（建议附）

- 固定 E1–E3、r=10%，对关键要素（份额±、净利率±）做单向敏感
- 或直接用 `sensitivity` 展示不同 L 对应市值，标注四档 L 位置

## 三、投资建议框架（仅用户明确要求建议时）

### 3.1 原则

- **条件化**，不喊单：用「若信号 A 且位置 B → 框架动作 C」
- 框架动作用语：关注/等待更佳赔率/分批/降低风险暴露/持有观察——避免「立即满仓买入」「清仓」等绝对指令
- 必须绑定**可观察检验信号**（订单、价格、份额数据、产能利用率、政策、一致预期上修等）
- 重申：公开信息推演，**不构成正式投资建议或收益承诺**

### 3.2 建议结构模板

1. **前提摘要**：现价隐含 L 与本方情景位置（引用第二节结论）
2. **多空关键变量**：2–4 个决定 L 上修/下修的变量
3. **信号→动作表**

| 观察信号 | 验证方向 | 框架含义（非指令） |
| --- | --- | --- |
| … | 上修 L / 下修 L | 赔率改善关注 / 风险积聚宜谨慎 |

4. **情景失效条件**：何种事实会推翻本方基准/乐观档
5. **免责**：独立决策、结合自身风险承受力

### 3.3 禁止

- 保证收益、保本表述
- 未做情景就给买卖结论
- 用 PE 拍脑袋目标价替代 DCF 正算
- 把增补段落静默写进默认报告「核心结论」冒充客观列示

## 四、交付

- 文件名优先：`{公司名}_穿透叙事_情景与建议增补.md`
- 或在原 md 末追加二级标题：`## 追问增补：本方情景与（可选）建议框架`，文首注明「本节应用户追问生成，非默认报告组成部分」
- 按 `report-spec.md` 第五节结构写作，并读取原客观材料、已有默认报告（若有）及财务/反算中间件
- 对话追问且用户只要口头结论：可对话输出精简情景表+位置+（若要）框架建议，数字须与脚本一致
