# 事实辩论 Skill

对用户提出的投研观点进行多源数据检索，并基于检索到的客观事实生成辩论式质疑报告。

## 核心原则（最高优先级）

1. **执行要求**：组织正反证据检索、读取材料、判断命题真伪并完成写作。`search_paipai` 和 `doc_searcher` 只提供证据，不能替代事实辨析。
2. **证据处理**：检索阶段不要无依据地截断原文；`doc_searcher` 通过 `save_as` 将结果保存到独立文件。写作阶段必须读取正反关键证据，核对主体、时间、口径和来源质量。
3. **中间文件与交付**：搜索类结果通过 `save_as` 保存，避免无意义地占用上下文；不要用 `write_file` 伪造未检索到的证据。最终辨析使用 `write_file` / `replace_file` 写入交付文件。
4. **检索扩展**：除下方规定的检索任务外，可根据对用户观点的理解，发起额外的 `doc_searcher` 检索来补充有价值的数据，如相关行业数据、上下游信息、历史对比。
5. **doc_searcher 零结果容错**：当某个 doc_searcher 委托返回空结果时，自动扩大时间范围（如从最近1年扩大到最近2年）重试一次。若仍为空则跳过该文件，不影响其他检索和最终合并流程。

## 输入要求

必须从用户获取：
- **user_claim**：用户的观点/论点（如"光伏行业明年将迎来拐点"、"茅台的护城河正在削弱"）

可选信息（从观点中自动提取）：
- 涉及的公司名称和股票代码
- 涉及的行业名称
- 观点的时间维度

## 工作流程

### Step 1：观点解析与检索策略制定

#### 任务
- 从用户观点中提取核心论点，拆解为可检索的子命题（3-5个）
- 识别观点涉及的实体：公司（提取股票代码）、行业、产品、政策等
- 为每个子命题设计**正向验证**和**反向质疑**两组检索关键词
- 如果用户提到了具体公司但未给出股票代码，通过搜索确认

**示例**：
用户观点："XX公司明年产能翻倍，业绩将大幅增长"
- 子命题1：产能扩张计划 → 正向关键词：产能扩张/新建产线/资本开支；反向关键词：产能过剩/开工率下滑/扩产延期
- 子命题2：业绩增长预期 → 正向关键词：营收增长/订单增长/盈利预测；反向关键词：毛利率下滑/价格战/需求不及预期
- 子命题3：行业竞争格局 → 正向关键词：市占率提升/竞争壁垒；反向关键词：新进入者/替代技术/份额流失

### Step 2：多源并行检索

根据 Step 1 的检索策略，通过 `delegate_to_agent` 委托 `doc_searcher`、`search_paipai` 和 `search_web` 并行检索。所有委托**并行发起**。

#### 2A：doc_searcher 精确检索（按子命题并行）

为每个子命题发起一个 doc_searcher 委托，同时覆盖正向和反向关键词：

```python
delegate_to_agent(
    agent_type="doc_searcher",
    instruction="检索[公司名/行业名]相关的研报、纪要和点评，时间范围：最近1年。正向关键词：[正向关键词列表]；反向关键词：[反向关键词列表]。每组关键词返回10-15条，返回标题、时间/日期、正文和机构名称。各语义检索调用须带 `save_as` 将结果完整保存，禁止对内容做任何筛选或截断。完成后在回复中列出已保存的文件路径及各文件的内容概要。结果保存为 tmp/{session_id}/01_topic_{N}.md。"
)
```

如果涉及具体公司，额外发起公告检索：

```python
delegate_to_agent(
    agent_type="doc_searcher",
    instruction="检索[公司名]（[股票代码]）最近1年的公告，重点关注与[观点主题]相关的内容（如产能、业绩、资本开支、合同、诉讼等）。返回10条，按发布时间降序，返回标题、发布时间、公告类型和正文。对年报、中报等长篇定期报告，只返回与主题最相关的2~3段，不取回无关全文；临时公告返回正文。各语义检索调用须带 `save_as` 将检索结果完整保存，禁止对已返回内容做二次筛选或截断。完成后在回复中列出已保存的文件路径及各文件的内容概要。结果保存为 tmp/{session_id}/02_announcements.md。"
)
```

#### 2B：search_paipai 语义检索

使用 `search_paipai` 进行语义检索，分两个方向：

**背景信息检索**：获取与观点相关的基础背景和市场共识：

```python
search_paipai(
    query="[观点涉及的核心实体] [行业/公司] 最新动态 市场观点",
    sources=["report", "roadshow", "comment"],
    top_k=15,
    save_as="tmp/{session_id}/03_paipai_bg.md"
)
```

**反向视角检索**：重点捕获与用户观点**相反立场**的内容：

```python
search_paipai(
    query="[用户观点的反面表述] [关键实体]",
    sources=["report", "roadshow", "comment"],
    top_k=20,
    save_as="tmp/{session_id}/04_semantic_counter.md"
)
```

#### 2C：互联网公开信息补充

使用 `search_web` 检索：
- 相关行业/公司的最新动态与争议
- 第三方数据源（如产能利用率、价格走势、政策变化）
- 市场上对该观点的不同声音

将结果通过 `save_as` 参数保存为 `tmp/{session_id}/05_web_info.md`。

#### 2D：自由补充检索（可选）

可根据对用户观点的理解，发起额外的 `doc_searcher` 委托检索其他有价值的数据，如相关行业数据、上下游产业链、历史类似案例；结果保存为 `tmp/{session_id}/90_extra_{N}.md`。

### Step 3：生成事实辨析报告

1. 读取 `references/report-prompt.md`，按其中结构组织证据、判断和结论。
2. 读取正反证据文件，逐项核对用户观点中的事实、口径、时间和隐含假设；区分被证据支持、被反驳和尚无法判断的部分。
3. 完成事实辨析，并使用 `write_file` 写入 `tree/fact_debate_{主题简称}.md`。
4. 交付前核对相反证据是否被公平呈现、每个判断是否有证据支撑，并在聊天中给出核心结论与文件链接。

## 注意事项

1. **检索必须覆盖正反两面**：不能只检索支持用户观点的材料，必须主动检索反向证据。反向检索是本 skill 的核心价值
2. **子命题拆解要具体**：不要笼统地搜索，而是将大观点拆成可验证的小命题，每个命题独立检索
3. **doc_searcher instruction 写作规范**：每次委托时，instruction 中必须包含内容类型（研报/纪要/点评/公告）、实体（股票代码或行业名）、时间范围（YYYY-MM-DD）、正向和反向关键词、期望返回字段
4. **最终报告形成**：完成事实辨析和写作；不得把最终写作转交给 SubAgent 或额外的写作模型
